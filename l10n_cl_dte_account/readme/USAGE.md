Set the company SII mode to Demo from Settings > Companies, then select
**Prepare Demo Configuration** beside the mode selector. Choose one or more
Chilean DTE types in the tag field. The confirmation wizard creates a synthetic
Demo trust key, one signed CAF for each selected type, and a disposable company
signing certificate/profile. Type 33 is selected by default. The company must
have a valid Chilean RUT. Existing CAFs and signing profiles are never changed;
the wizard can add missing synthetic CAF types to an existing synthetic Demo
profile.

After setup, post a customer invoice using document type 33 or 34 and choose
**Issue DTE** in the invoice header. The selected type determines the CAF,
folio, TED, XML and durable submission. Type 34 requires exempt-only invoice
lines. The asynchronous Demo gateway simulates submission and status polling;
its TrackID and evidence are clearly marked `DEMO / SIMULADO`. They are not an
SII receipt. The queue-job runner must be active to process the submission.

If an invoice is reset to draft before a DTE is created, its document type can
be changed. The accounting number is recomputed when it is posted again. Types
39 and 41 are boletas with a separate SII XML format and reporting lifecycle;
this invoice DTE adapter does not expose **Issue DTE** for them yet. Other CAF
types generated by the setup wizard are prepared for future source-document
flows and cannot yet be issued from customer invoices.

The generated trust key, CAF private key, and signing certificate are synthetic
local test material. Never use them in Certification or Production. Those modes
remain unavailable until their real SII transport adapters are installed.
